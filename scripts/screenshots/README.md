# Скриншоты для статей

Интерактивный мастер создаёт тёмную и светлую версии скриншотов и вставляет theme-aware разметку в Markdown-статью.

## Подготовка статьи

Добавьте отдельной строкой один или несколько маркеров:

```md
[скриншот]
```

Рекомендуется сразу задать стабильное имя:

```md
[скриншот: filters-panel]
```

Имя используется в названиях файлов. Если его нет, мастер предложит `01-screenshot`, `02-screenshot` и так далее.

Для изображения, которое создаётся один раз и не должно попадать в будущую массовую актуализацию скриншотов, используйте:

```md
[картинка: spread-reversal]
```

Такое изображение снимается и оптимизируется тем же способом, но получает признаки `data-media-kind="illustration"` и `data-refresh="manual"`.

## Запуск

```bash
npm run screenshots -- src/content/docs/tools/stat-screener/overview.md
```

Проверить распознанные маркеры без запуска браузера:

```bash
npm run screenshots -- src/content/docs/tools/stat-screener/overview.md --list
```

При необходимости можно задать стартовую страницу и параметры оптимизации:

```bash
npm run screenshots -- src/content/docs/tools/stat-screener/overview.md \
  --url https://spread-i.online/ \
  --width 1600 \
  --quality 90
```

## Работа в браузере

1. При первом запуске войдите в Spread Insight. Авторизация сохранится в отдельном локальном профиле `.cache/screenshot-browser`.
2. Перейдите на нужную страницу и приведите приложение в состояние, которое должно попасть в статью.
3. В панели мастера проверьте имя, `alt` и необязательную подпись.
4. Нажмите **Выделить область** и протяните рамку.
5. При необходимости нажмите **Рамка** или **Стрелка** и нарисуйте аннотацию внутри выбранной области. Кнопки `↶` и `×` удаляют последнюю или все аннотации.
6. Проверьте автоматически рассчитанную **Ширину в статье**. Она равна ширине выделенной области и не даёт маленьким фрагментам растягиваться на всю колонку.
7. Установите тёмную тему в приложении и нажмите **Снять тёмную**.
8. Не меняя область и состояние страницы, установите светлую тему и нажмите **Снять светлую**.
9. Нажмите **Вставить в статью**.

Панель можно переместить в левый или правый верхний угол кнопкой `↔`. В готовый снимок она не попадает.

## Результат

Файлы сохраняются по структуре статьи:

```text
public/help-assets/screenshots/tools/stat-screener/overview/
├── filters-panel-dark.webp
└── filters-panel-light.webp
```

Маркер заменяется на `<figure class="si-themed-screenshot">` с двумя изображениями. Общие стили показывают версию, соответствующую выбранной теме Starlight. Физическое разрешение файла и ширина показа хранятся отдельно: файл остаётся чётким, но небольшой фрагмент не увеличивается сверх выбранного размера.

Рамки и стрелки сохраняются отдельным SVG-слоем поверх изображений. Один слой используется для обеих тем, масштабируется вместе с изображением и не изменяет исходные WebP-файлы.

Обе версии снимаются с одинаковой областью и проверяются на совпадение размеров. Исходный снимок создаётся с двойной плотностью пикселей, после чего уменьшается до заданной максимальной ширины и сохраняется в WebP.

## Аннотации на уже созданных изображениях

Чтобы добавить или изменить рамки и стрелки без пересъёмки, запустите:

```bash
npm run screenshots -- src/content/docs/tools/stat-screener/overview.md --annotate
```

Мастер откроет все тематические изображения статьи по очереди. Добавьте аннотации и нажмите **Сохранить аннотации** либо нажмите **Пропустить**, чтобы оставить конкретное изображение без изменений. В этом режиме WebP-файлы не перезаписываются.

## Ограничения первого этапа

- Тему Spread Insight нужно переключать вручную.
- Область задаётся координатами окна и не сохраняется для повторной съёмки.
- Изменения статьи записываются после обработки всех маркеров; пропущенные маркеры остаются без изменений.
- Команда массовой актуализации всех скриншотов по сохранённым областям пока не реализована; тип `картинка` уже сохраняется для неё как исключение.
